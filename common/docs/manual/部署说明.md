# IXPay Pro 部署说明

## 1. 系统架构概述

IXPay Pro 是一个基于 Go + Vue3 的前后端分离支付管理系统，采用微服务架构设计。后端使用 Gin 框架开发 RESTful API，前端使用 Vue3 + Element Plus 构建现代化界面。

### 1.1 技术栈

**后端**：
- Go 1.26.5 
- Gin Web 框架
- GORM ORM 框架
- PostgreSQL 数据库
- Redis 缓存
- JWT 认证

**前端**：
- Vue 3
- Element Plus
- TypeScript
- Vite

### 1.2 部署模式

IXPay Pro 支持两种部署模式：

1. **单实例模式 (all)**: 适用于开发环境或单节点部署
   - `node_role: "all"` - 同时运行 API 服务和 Task 任务

2. **多实例模式 (api/task 分离)**: 适用于多节点分布式部署
   - `node_role: "api"` - 只运行 API 服务
   - `node_role: "task"` - 只运行 Task 任务

## 4. Docker 部署（推荐）

### 4.1 前置条件

- Docker Desktop 已安装并运行
- PostgreSQL 容器运行中（容器名：pgsql-pgsql-5432-1）
- Redis 容器运行中（容器名：app-redis-1）
- Nginx 容器运行中（容器名：nginx-1.30.0，可选）

### 4.2 目录结构

```
run/
├── README.md                      # 部署说明文档
├── deploy.bat                     # 后端一键部署脚本
├── deploy-web.bat                 # 前端部署脚本
├── server/                        # 后端服务目录
│   ├── docker-compose.yml         # ← 统一的编排配置（重要！）
│   ├── server-1/                  # API 节点 1 (端口 8081)
│   │   ├── config.yaml
│   │   └── logs/
│   ├── server-2/                  # API 节点 2 (端口 8087)
│   │   ├── config.yaml
│   │   └── logs/
│   └── server-3/                  # Task 节点 (端口 8088)
│       ├── config.yaml
│       └── logs/
├── web/
│   └── ixpay.conf                 # Nginx 配置
└── gxy/
    ├── config.json
    ├── gateway
    └── start-gateway.bat          # 网关启动脚本

server/
├── Dockerfile                     # Docker 镜像文件
├── build-for-docker.bat           # 编译脚本
├── .dockerignore                  # Docker 忽略文件
├── docker-compose.yml             # 单实例示例配置
└── configs/
    └── config.yaml                # 基础配置模板
```

**重要说明**：
- 所有容器实例的编排配置统一在 `run/server/docker-compose.yml`
- 使用 `depends_on` + `condition: service_healthy` 确保启动顺序
- 只有 `server-1` 完成初始化后，`server-2` 和 `server-3` 才会启动

### 4.3 快速部署

#### 方法一：使用部署脚本（推荐）

```powershell
# 1. 部署后端服务（3 个实例，自动按依赖顺序启动）
cd run
.\deploy.bat

# 2. 部署网关服务
cd gxy
..\gxy\docker-compose-gxy.yml up -d

# 3. 部署前端服务
cd ..
.\deploy-web.bat
```

**部署脚本说明**：
- 自动创建必要的日志目录
- 自动编译 Go 二进制文件（Linux amd64）
- 一键启动所有服务（按依赖顺序）
- 等待服务健康检查完成

#### 方法二：手动部署

```powershell
# 1. 创建目录
mkdir run\server\server-1\logs
mkdir run\server\server-2\logs
mkdir run\server\server-3\logs

# 2. 编译二进制文件
cd server
.\build-for-docker.bat

# 3. 启动所有实例（一条命令即可！）
cd ..\run\server
docker-compose up -d

# 4. 启动网关
cd ..\gxy
docker-compose -f ..\gxy\docker-compose-gxy.yml up -d

# 5. 部署前端
cd ..\web
npm install
npm run build
xcopy /E /Y /I dist D:\1_Software\Docker\Nginx-1.30.0\html
copy web\ixpay.conf D:\1_Software\Docker\Nginx-1.30.0\conf\conf.d\
docker exec nginx-1.30.0 nginx -s reload
```

### 4.4 配置说明

#### 统一的 Docker Compose 配置

**重要改进**：所有容器实例统一在 `run/server/docker-compose.yml` 配置，优势：

1. **集中管理**：一个文件管理所有实例
2. **依赖启动**：自动按顺序启动，确保数据初始化完成
3. **健康检查**：每个实例都有独立的健康检查配置
4. **简化操作**：一条命令启动所有服务

**依赖关系配置**：

```yaml
services:
  ixpay-server-1:
    # ... 配置 ...
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost:8081/health"]
      interval: 10s
      timeout: 5s
      retries: 3
      start_period: 30s

  ixpay-server-2:
    # ... 配置 ...
    depends_on:
      ixpay-server-1:
        condition: service_healthy  # 等待 server-1 健康后才启动

  ixpay-server-3:
    # ... 配置 ...
    depends_on:
      ixpay-server-1:
        condition: service_healthy  # 等待 server-1 健康后才启动
```

#### 节点角色配置

**API 节点** (server-1, server-2):
- `node_role: "api"` - 只运行 API 服务
- 处理 HTTP 请求
- 端口：8081, 8087
- `init_seed_data: true` (仅 server-1) - 初始化种子数据

**Task 节点** (server-3):
- `node_role: "task"` - 只运行定时任务
- 处理后台任务
- 端口：8088
- `init_seed_data: false` - 不初始化种子数据

#### 关键配置差异

每个节点的配置差异：
- `server.port`: 服务端口 (8081/8087/8088)
- `server.machine_id`: 机器 ID (1/2/3)
- `server.node_id`: 节点唯一标识
- `server.node_role`: 节点角色 (api/task)
- `server.init_seed_data`: 是否初始化种子数据（仅首个 API 节点为 true）

### 4.5 网关配置

网关负责服务发现和负载均衡：

```json
{
  "listen_addr": "0.0.0.0",
  "listen_port": 8085,
  "enable_auto_discovery": true,
  "register_auth_key": "ihvke@2025"
}
```

所有后端服务会自动注册到网关，网关进行健康检查和负载均衡。

### 4.6 Nginx 配置

前端使用 Nginx 部署，配置文件位于 `run/web/ixpay.conf`：

```nginx
server {
    listen 80;
    server_name localhost;

    location / {
        root /usr/share/nginx/html;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    location /api/admin {
        proxy_pass http://host.docker.internal:8085;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 7. 故障排查

### 7.1 容器无法启动

1. 检查 Docker Desktop 是否运行
2. 检查端口是否被占用：`netstat -ano | findstr :8081`
3. 查看容器日志：`docker logs ixpay-server-1`

### 7.2 数据库连接失败

1. 确认 pgsql-pgsql-5432-1 容器运行：`docker ps | findstr pgsql`
2. 检查配置文件中 `postgres.host: "host.docker.internal"`
3. 确认防火墙允许 Docker 访问宿主机

### 7.3 Redis 连接失败

1. 确认 app-redis-1 容器运行：`docker ps | findstr redis`
2. 检查配置文件中 `redis.address: "app-redis-1:6379"`
3. 确认 Redis 容器与后端容器在同一网络

### 7.4 网关注册失败

1. 检查网关是否运行：`docker ps | findstr gxy`
2. 确认 `gateway_url` 配置正确
3. 确认 `auth_key` 一致（ihvke@2025）
4. 检查网络连通性

### 7.5 前端无法访问 API

1. 检查 Nginx 配置
2. 检查网关是否运行
3. 检查 CORS 配置

## 8. 配置说明

### 8.1 环境变量

| 变量名 | 描述 | 默认值 |
| --- | --- | --- |
| LOG_LEVEL | 日志级别（debug/info/warn/error） | info |
| SERVER_PORT | 服务端口 | 8081 |
| SERVER_MODE | 服务器运行模式（debug/release/test） | debug |
| JWT_SECRET | JWT 密钥 | 随机生成 |
| JWT_EXPIRE | JWT 过期时间（秒） | 1800 (30m) |
| REDIS_HOST | Redis 主机 | localhost |
| REDIS_PORT | Redis 端口 | 6379 |
| REDIS_PASSWORD | Redis 密码 | "" |
| REDIS_DB | Redis 数据库编号 | 0 |
| DB_HOST | 数据库主机 | localhost |
| DB_PORT | 数据库端口 | 5432 |
| DB_USER | 数据库用户 | ixpay |
| DB_PASSWORD | 数据库密码 | ixpay123 |
| DB_NAME | 数据库名称 | ixpay_pro |
| DB_SSLMODE | 数据库 SSL 模式 | disable |

### 8.2 配置文件

主要配置文件位于 `server/configs/config.yaml`，包含以下主要部分：

- **server**: 服务器配置（端口、运行模式、节点角色、种子数据初始化等）
- **postgres**: PostgreSQL 数据库配置（连接池、超时等）
- **redis**: Redis 配置（连接池、键前缀等）
- **jwt**: JWT 认证配置（双令牌机制：access_token + refresh_token）
- **logging**: 日志配置（格式、文件路径、日志分割等）
- **gateway**: 网关注册配置（可选，用于多实例部署）
- **swagger**: Swagger 文档配置

## 9. 安全建议

1. **生产环境配置**：
   - 修改默认密码
   - 启用 HTTPS
   - 配置防火墙规则
   - 限制 API 访问 IP

2. **数据库安全**：
   - 使用强密码
   - 限制数据库访问 IP
   - 定期备份数据库

   - 定期更新依赖包
   - 启用输入验证
   - 防止 SQL 注入
   - 防止 XSS 攻击

## 11. 网络架构

### 11.1 容器网络拓扑

```
外部请求
    ↓
Nginx (:80)
    ↓
gxy-gateway (:8085)
    ↓
┌───────────┬───────────┬───────────┐
│   :8081   │   :8087   │   :8088   │
│  (API)    │  (API)    │  (Task)   │
│ server-1  │ server-2  │ server-3  │
└───────────┴───────────┴───────────┘
    ↓             ↓             ↓
pgsql-pgsql-5432-1    app-redis-1
```

### 11.2 启动顺序

```
1. ixpay-server-1 启动
   ↓
2. 健康检查通过 (约 30 秒)
   ↓
3. ixpay-server-2 和 ixpay-server-3 同时启动
   ↓
4. 所有节点注册到网关
   ↓
5. 服务完全可用
```

### 11.3 网络配置

所有容器通过 Docker 网络 `ixpay-network` 连接：
- 容器间可通过容器名互相访问
- 通过 `host.docker.internal` 访问宿主机上的数据库和 Redis
- 网关自动发现并注册所有后端服务
